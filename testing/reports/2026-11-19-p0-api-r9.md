## 2. 初跑失败与缺陷

### BUG-API-010（S2）hidden 附件字段的元数据与下载未按字段权限裁剪

- 用例：`test_hidden_attachment.py::test_hidden_attachment_field_visibility_and_download`
- 现象：发起人运行中 `render.attachments` 仍包含 hidden 附件字段的文件名；按附件 ID 下载仍返回 200。
- 根因：
  1. 绑定附件时只记 `instance_id`，没有记 `field_key`，后续无法按字段权限过滤；
  2. render 的 `attachments` 列表未按权限裁剪；
  3. 下载鉴权只校验“能看实例”，未校验“能看该附件所属字段”。
- 修复：
  - `collect_attachment_fields` 收集“附件 id → 字段 key”，绑定到实例时写入 `attachment.field_key`（含子表列）；
  - `render` 的 attachments 只保留无字段归属的说明附件或可见字段的附件；
  - 下载鉴权对带 `field_key` 的附件复用 render 的字段权限，hidden 字段直接 403。
- 影响：hidden 附件字段的文件名/下载入口对所有能看实例的人可见，属于 D-04 泄露。

## 3. 环境限制：转办 vs 同意并发

- 在 SQLite 上同时执行转办与同意会触发 `instance_actions` 唯一约束冲突并返回 500。
- 原因是 SQLite 不支持 `SELECT ... FOR UPDATE` 行锁；目标形态 MySQL 8 会通过实例行锁串行化。
- 用例已在 SQLite 下 `skip`，需在 MySQL 部署环境复跑；未计入通过。
