## 2. 实现说明

- 造数统一走 API 工厂（`fixtures/factories.ts`）：自建表单/流程并真实发布，不直接改库。
- 关键交互走真实页面：发起、草稿续填、同意/驳回/退回、转办、追加字段、导出、消息已读。
- 每条用例同时断言界面可见结果与后端副作用（`render` / `todo` / 导出文件内容）。
- 为避免 antd 控件内部结构变化，定位优先 `getByRole` / `getByPlaceholder` / `getByTestId`；仅为日期面板与文件下载使用少量第三方内部类。
- 发起中心补了 `data-testid="flow-card"` / `data-testid="draft-item"`，避免草稿与流程同名时选择器歧义。

## 3. 本轮观察（非缺陷）

| 观察 | 说明 |
|---|---|
| 已有人处理过时，「撤回」按钮仍显示 | 前端只在 RUNNING 且本人是发起人时展示；服务端按 PRD §3.5.4 拒绝并提示「已经有任务被处理过…」。当前行为符合服务端权威语义，UI 是否提前隐藏留待产品确认。 |
| 详情页同一字段值出现两处 | 页面同时渲染屏幕表单与打印文档（`PrintDocument`），属预期结构；断言取第一处。 |

## 4. 本轮未覆盖 / 需确认

- 打印只验证「点击触发 `window.print`」，A4 分页与排版仍需人工验收（PRINT-01）。
- 委托创建走接口准备，UI 只覆盖列表与取消；RangePicker 双面板交互未自动化。
- 业务字段筛选器（多操作符组合）UI 未覆盖，API 侧已在 G1 覆盖。
- 快照回放/差异对照的页面点击路径未覆盖（接口与 G1 已覆盖裁剪语义）。
- 设计器只覆盖「建表单加字段发布」「建流程用默认审批节点发布」；条件/并行/字段权限的图形化配置未自动化。
- 通知「≤10s 感知」未做轮询时延断言。
- 仅 Edge + Windows；Chrome/其他平台未跑。
