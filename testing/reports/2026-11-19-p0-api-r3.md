## 2. 初跑失败与缺陷

### BUG-API-006（S1）转办后流程永远停在 RUNNING

- 用例：`test_delegation.py::test_transfer_reassigns_pending_task`
- 现象：转办后目标人同意，动作返回 `to_status=RUNNING`；实例没有任何待办，时间线只有 SUBMIT / TRANSFER / AGREE。
- 根因：转办把原指派置为 `CANCELLED/TRANSFERRED` 并新建指派；节点聚合仍把原指派算进 `task.assignments`，SINGLE/ALL 认为“还有人未完成”，节点永远 OPEN。
- 修复：`_assignment_views` 过滤 `CANCELLED + cancel_reason=TRANSFERRED` 的指派，不参与节点聚合。

### BUG-API-007（S2）转办/委托的原处理人看不到实例

- 用例：`test_delegation.py::test_delegation_routes_new_task_to_delegatee`
- 现象：委托生效、被委托人处理完成后，委托人 `GET /instances/{id}/render` 返回 403。
- 根因：`can_view` 只查 `TaskAssignment.user_id`，未查 `origin_user_id`；列表查询 `build_query` 已经支持 origin，但详情/导出/快照走的是 `can_view`。
- 修复：`can_view` 同时匹配 `user_id` 或 `origin_user_id`（PHASE3 M14 §4.4）。
