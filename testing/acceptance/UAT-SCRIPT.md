# UAT 走查脚本（内部试用）

> 环境：`http://localhost:5173`（后端 `http://127.0.0.1:8000`，独立 SQLite，可随时重置）
> 账号见 `testing/.runtime/e2e/accounts.md`；密码：admin `admin123456`，其余 `demo123456`。
> 原则：只记录“期望 vs 实际”，不现场改代码；问题按严重级别登记，修复后补回归用例。

## 1. 设计者：配置一条新流程（zhaoliu）

1. 登录 zhaoliu → 「表单模板」→ 新建表单，名称如 `UAT 测试表单`。
2. 添加两个字段：`事由`（单行文本，必填）、`金额`（数字）；保存并发布。
3. 「流程模板」→ 新建流程，绑定刚发布的表单；使用默认审批节点，发布。
4. 退出，用 zhangsan 登录，确认「发起中心」能看到这条新流程。

期望：发布后立即可发起；字段与流程配置一致。

## 2. 发起人：填写、暂存、提交（zhangsan）

1. 「发起中心」→ 请假申请。
2. 填假别/起止日期/事由，先不提交，等 2 秒看到「已暂存」。
3. 返回发起中心 →「我的草稿」→「继续填写」，确认内容还在。
4. 提交审批，进入详情页；确认状态「审批中」、当前节点、单号。

期望：草稿可恢复；提交只生成一个实例；详情页字段与填写一致。

## 3. 审批人：同意与驳回重提（lisi ↔ zhangsan）

1. lisi 登录 →「工作台/待办」→ 打开刚才的单据。
2. 本次先点「驳回」，填写驳回意见（必填），确认。
3. zhangsan 打开该单，看到驳回意见；点「修改并重新提交」，改事由后提交。
4. 确认详情页显示「第 2 轮」、状态「审批中」。
5. lisi 再次处理，点「同意」，确认状态「已通过」。

期望：驳回必须写意见；重提轮次 +1 并从头重走；同意后归档。

## 4. 管理员：检索与导出（admin）

1. 登录 admin →「实例管理」。
2. 确认刚通过的单据在归档中；运行中的单据不在归档。
3. 按单号/标题搜索；导出 CSV，用 Excel 打开确认中文不乱码、列完整。
4. 打开一条归档单据，确认字段、处理历史完整。

期望：归档只含已通过；CSV 含动态字段；普通用户不能访问归档导出。

## 5. 打印（zhangsan 或 lisi）

1. 打开任一单据详情 → 点「打印」。
2. 在打印预览中检查：A4 分页、字段值、审批意见/时间线、hidden 字段是否泄露。
3. 另存为 PDF，检查页码与边距。

期望：内容不截断、不泄露无权字段、分页合理。

## 6. 移动端（可选）

浏览器开发者工具切 390×844，走「发起中心 → 填写 → 详情」，确认无横向滚动、按钮可点。
