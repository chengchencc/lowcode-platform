## 3. 已确认决策（2026-11-19）

### D-01 部门主管的解析口径

- **冲突**：PRD §3.3.2 写“发起人所在部门的‘主管’角色用户”；REQ-OPT §三写“部门主管动态解析、沿部门树向上找”；TECH/TEST-DATA 使用部门主管人（`manager_user_id`）。
- **确认结论**：以部门设置的主管人为准；本部门无主管时沿部门树向上找最近主管；根部门仍无主管则转平台管理员并在任务上标记异常。主管角色不作为派单来源（角色多成员时无法确定唯一处理人）。
- **影响**：ORG-01-b、ORG-02、INIT-04、REJECT/RETURN 的派单与兜底断言。
- **回写状态**：已回写 PRD §3.3.2（2026-11-19）。

### D-02 设计者能看到哪些审批数据

- **冲突**：PRD §2 写“设计者无审批数据管理权”；TECH §6.1 把 `/admin/instances` 列在 designer 路由下；PHASE3 §1 又给设计者管理概览/管理入口。
- **确认结论**：设计者可维护表单/流程模板、查看自己发起的实例；不可查看全量实例或他人审批数据；`/admin/instances` 仅管理员；首页管理概览仅管理员，设计者只显示个人工作台。
- **影响**：PERM-03-b、SEC-01-d、DASH-01-c/e。
- **回写状态**：已回写 PRD §2、TECH §6.1、PHASE3 §1/§10（2026-11-19）。

### D-03 并行组里有人“退回”的语义

- **冲突**：PRD §3.5.3 写“并行组任一子任务驳回/退回 → 组失败，按驳回策略处理整实例”；PRD §3.5.4 / TECH §4.4 写“退回时实例仍 RUNNING，取消目标之后令牌并重派”。
- **确认结论**：退回是节点级动作，不按“组失败/整单驳回”处理。并行组内任一成员退回 → 取消整个并行组及后续令牌（其余成员任务取消并知会），实例保持 RUNNING，在目标节点重派。
- **影响**：TASK-04、RETURN-01、引擎令牌语义。
- **回写状态**：已回写 PRD §3.5.3、TECH §4.4（2026-11-19）。

### D-04 hidden 字段的严格程度与终态视角

- **确认结论**：
  - 运行中：按查看者权限严格隐藏——字段值、附件元数据、导出/打印内容都不出现；前端只下发可见字段的 schema，不泄露 hidden 字段的 key/标签。
  - 终态：按 TECH §4.5 的归档视角，参与者/管理员可查看全量字段（只读），无关人员仍不可见。
  - 历史快照：按查看者当前权限 + 快照时点数据呈现；运行中查看历史快照仍受当前权限约束。
- **影响**：PERM-02/03/04、SEC-02、ARCHIVE-01、打印。
- **回写状态**：已回写 TECH §4.5/§6.2（2026-11-19）。

### D-05 归档列表的状态范围（默认执行）

- **确认结论**：归档列表固定只显示 APPROVED；管理员“实例管理”可查询全部状态；`/instances/archive` 不接受非 APPROVED（或仅管理员可传其他状态）。
- **影响**：ARCHIVE-01-a/b、导出、UAT。
- **状态**：2026-11-19 按推荐默认执行；已回写 PRD F8.1。如需多状态口径再调整。

## 4. 我将采用的实现默认（不需要你拍板）

| # | 事项 | 默认 |
|---|---|---|

| 10 | 性能 | P0 用 1k 数据验收，列表/筛选 P95 < 2s；10k 为扩展；MySQL 300/500ms 作为工程诊断指标 |

| 17 | 单实例导出/打印 | 能查看实例的参与者可导出/打印；归档批量导出仅管理员 |
| 18 | 审计范围 | 管理端审计仅管理员；失败越权尝试不要求写审计 |
