## 3.1 AUTH-01 登录 / 登出 / 改密 / 停用

### AUTH-01-a 正确凭据登录、访问受保护页面、登出后旧会话失效

- **需求来源**：PRD F6.4（登录态/JWT/会话过期）；TECH §3.2（登出使 token 失效）、§5.1（认证端点）；TEST-PLAN §6.1 AUTH-01
- **优先级**：P0
- **验证层**：API+E2E
- **前置条件**：
  - 角色与组织：`zhangsan` 为技术部普通用户，状态 `ACTIVE`，密码 `demo123456`。
  - 表单/流程版本与状态：无需表单或流程。
  - 实例状态与数据：无。
- **步骤**：
  1. 浏览器打开 `/login`，输入 `zhangsan` / `demo123456`，点击登录。
  2. 记录登录后跳转的 URL 和页面可见的姓名/部门。
  3. 用 API 以同一账号调用 `POST /api/v1/auth/login`，保存返回的 `access_token`、`refresh_token`。
  4. 用该 `access_token` 调用 `GET /api/v1/auth/me`。
  5. 在浏览器中点击“退出登录”；随后用第 3 步保存的旧 `access_token` 调 `GET /api/v1/auth/me`，用旧 `refresh_token` 调 `POST /api/v1/auth/refresh`。
  6. 浏览器后退到登录前的受保护页面，刷新。
- **期望结果**：
  1. 页面/接口：登录后跳转到 `/dashboard` 或系统首页，页面显示“张三”和“技术部”；`/auth/me` 返回 `200`，`user.username="zhangsan"`、`is_admin=false`、`is_designer=false`；登录响应含 `access_token`、`refresh_token`、`expires_at`、`user`。
  2. 数据副作用：无业务数据产生；登出接口返回 `{"ok": true}`。
  3. 通知/审计副作用：无新增业务通知。
  4. 登出后旧 `access_token` 访问 `me`、旧 `refresh_token` 刷新，均返回非 2xx（具体 401/403 见 Q-01/Q-02）；浏览器不能再显示受保护页面内容。
- **反例/边界**：
  - 未携带 token 直接访问 `/auth/me`：非 2xx，不返回任何用户信息。
  - 手工把旧 token 塞回浏览器本地存储后刷新：页面应回到登录页，不渲染用户名或业务菜单。
- **自动化位置**：`testing/e2e/specs/auth-org.spec.ts` + `backend/tests/test_acceptance_auth_org.py`
- **需求待确认项**：Q-01、Q-02、Q-30

### AUTH-01-b 错误密码与不存在账号返回一致提示，不泄露账号是否存在

- **需求来源**：TEST-PLAN §6.1 AUTH-01 关键期望；PRD F6.4；业务章程 §7（数据安全/访问控制）
- **优先级**：P0
- **验证层**：API+E2E
- **前置条件**：
  - 角色与组织：`zhangsan` 为启用用户；准备一个确定不存在的用户名 `E2E-<runId>-no-such-user`。
  - 表单/流程版本与状态：无。
  - 实例状态与数据：无。
- **步骤**：
  1. API 以 `zhangsan` + 错误密码 `wrong-password` 调 `POST /auth/login`，记录状态码与响应体。
  2. API 以不存在的用户名 + 任意密码调 `POST /auth/login`，记录状态码与响应体。
  3. 浏览器分别用上述两组凭据登录，记录页面提示文案。

### PERM-04-c 抄送人与处理人仅能看到可见字段的附件，hidden 字段附件不可见

- **需求来源**：PRD §3.4（字段级 hidden 含“文件”）；TEST-PLAN §6.4 PERM-02/PERM-04；TECH §8（下载权限）；需求方确认 R4（抄送人附件跟随字段权限）
- **优先级**：P0
- **验证层**：API+E2E
- **前置条件**：
  - 角色与组织：`zhangsan` 发起人；`lisi` 审批人；`wangwu` 填写节点处理人；`zhaoliu` 抄送人；`admin` 终审人；`E2E-<runId>-outsider` 无关用户。
  - 表单/流程版本与状态：表单含可见附件字段 `apply_file` 与隐藏附件字段 `supplement_file`（`visible_at_start=false`）；流程：开始 → 审批（`lisi`，`supplement_file` hidden）→ 填写（`wangwu`，`supplement_file` editable）→ 抄送（`zhaoliu`）→ 终审（`admin`）→ 结束。
  - 实例状态与数据：由本用例发起，`zhangsan` 提交时上传 `apply_file=F4`；`wangwu` 在填写节点上传 `supplement_file=F3` 并提交；实例随后到达抄送节点并停在终审。
- **步骤**：
  1. 在 `lisi` 审批节点、`zhangsan` 发起人视图、`outsider` 视图中查看详情与打印，查找 `supplement_file`/`F3` 的文件名、附件 ID、下载入口。
  2. 分别用 `lisi`、`zhangsan`、`outsider` 调 `GET /files/{F3}` 与 `/download`；用 `lisi`、`zhangsan` 调 `GET /files/{F4}` 与 `/download`。
  3. 实例到达抄送后、终审完成前，`zhaoliu` 打开详情与打印，尝试下载 `F4` 与 `F3`。
  4. 流程结束后，`zhangsan` 查看归档详情与打印，确认 `supplement_file` 的归档可见性。
- **期望结果**：
  1. 页面/接口：运行中 `lisi` 与 `zhangsan` 的详情/打印不显示 `supplement_file` 及 `F3`；`lisi`、`zhangsan`、`outsider` 下载 `F3` 均返回 403/404（R4：hidden 字段附件不可见）；`outsider` 对 `F4` 也返回 403/404；`lisi`（可见字段的当前处理人）可下载 `F4`，`zhangsan`（上传者/发起人）可下载 `F4`。
  2. 数据副作用：`F3`、`F4` 均绑定实例并进入快照/归档数据；`zhaoliu` 在抄送节点可见 `apply_file` 并可下载 `F4`，但 `supplement_file` 与 `F3` 在其详情/打印中不可见，下载 `F3` 返回 403/404（R4）；归档后 `zhangsan` 按归档视角可见 `supplement_file` 字段（TECH §4.5），此时附件按该可见性可下载。
  3. 通知/审计副作用：`wangwu` 上传附件不向无权者发内容通知；时间线对无权者不显示 hidden 字段文件名；抄送通知不包含 `F3`。
- **反例/边界**：
  - hidden 附件字段的 CSV 导出：不得出现文件名/附件 ID（与 PERM-02-a 一致）。
  - 抄送人即使能打开实例详情，也不因“实例参与者”身份绕过字段权限看到 hidden 附件（R4）。
  - 附件元数据在 `render` 响应中的边界见 D-04。
- **自动化位置**：`backend/tests/test_acceptance_permissions.py` + `testing/e2e/specs/permissions.spec.ts`
- **需求待确认项**：无（D-04 已关闭）
