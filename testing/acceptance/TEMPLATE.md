# 用例模板

复制下面的结构到模块用例文件。**期望结果必须是可观察、可断言的行为**，不要写"正确显示""正常工作"这类无法判定的描述。

```markdown
### CASE-ID 标题

- **需求来源**：PRD Fx.x / TECH-DESIGN §x.x / PHASE2 Mx / 业务章程 §x（至少一个）
- **优先级**：P0 / P1
- **验证层**：API / 浏览器 E2E / 手工 / API+E2E
- **前置条件**：
  - 角色与组织：
  - 表单/流程版本与状态：
  - 实例状态与数据：
- **步骤**：
  1. ……
  2. ……
  3. ……
- **期望结果**：
  1. 页面/接口可观察结果：……
  2. 数据副作用：……
  3. 通知/审计副作用：……
- **反例/边界**（可选）：
  - 越权访问时：……
  - 重复提交时：……
- **自动化位置**：`testing/e2e/specs/xxx.spec.ts` / `backend/tests/test_acceptance_xxx.py` / 待自动化
- **需求待确认项**（如有）：……
```

## 设计检查清单

- [ ] 期望结果能直接写成断言（文本、状态码、字段值、任务数、通知数、审计记录）。
- [ ] 至少有一个反例或边界（越权、非法状态、重复操作、空数据），核心机制必须有反向用例。
- [ ] 前置条件不依赖其他用例的执行顺序。
- [ ] 没有引用实现细节（函数名、内部字段、数据库表结构）。
- [ ] 需求来源真实存在；如果文档没写清楚，列在"需求待确认项"而不是自己补规则。
