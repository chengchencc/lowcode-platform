### 方案确认及工时评估（第 4 节点可编辑）

工时评估情况（多行文本）、项目组项目经理（人员）、信息网络部项目经理（人员）。

## 三、流程节点与审批人来源

| # | 节点 | 类型 | 审批人来源 | 可编辑内容 |
|---|---|---|---|---|
| 1 | 需求负责人审批 | 审批 | 表单字段「需求负责人」（默认发起人） | 申请信息只读 |
| 2 | 需求部门负责人审批 | 审批 | `dept_manager`：发起人所在部门的主管 | 申请信息只读 |
| 3 | 项目组项目经理分派经办人 | 填写 | 角色「项目组项目经理」 | 指定项目组经办 |
| 4 | 项目组经办评估并编写方案 | 填写 | 表单字段「项目组经办」 | 方案确认及工时评估 |
| 5 | 项目组项目经理审批 | 审批 | 角色「项目组项目经理」 | 方案区只读 |
| 6 | 信息网络部项目经理审批 | 审批 | 表单字段「信息网络部项目经理」（第 4 节点选择） | 仅「信息网络部项目经理意见」 |
| 7 | 信息网络部部门负责人审批 | 审批 | `dept_manager`：指定的信息网络部部门 | 仅「信息网络部负责人意见」 |
| 8 | 需求小组组长审批 | 审批 | 角色「需求小组组长」 | 指定上线执行人、复核人 |
| 9 | 上线执行人填写执行情况 | 填写 | 表单字段「上线执行人」 | 执行情况、执行日期 |
| 10 | 复核人填写复核情况 | 填写 | 表单字段「复核人」 | 复核情况、复核日期 |
| 11 | 需求负责人填写验证结果 | 填写 | 表单字段「需求负责人」（默认发起人） | 业务验证情况 |
| 12 | 需求部门负责人确认验证 | 审批 | `dept_manager`：发起人所在部门的主管 | 全部只读 |

关键能力用到的现有功能：

- 表单人员字段驱动派单：`form_user_field`（**显式选到发起人时允许自审**，
  因此需求负责人默认发起人时第 1/11 节点仍由发起人处理，而不是转管理员）
- 部门主管动态解析（沿部门树向上找）：`dept_manager`
- 角色派单 + 角色成员维护：`role`
- 填写节点补充字段：`fill` + 字段权限矩阵
- 按分区/字段控制每个节点可编辑性：`partitions` / `overrides`
- 发起时自动填充并锁定：申请人、申请部门、**申请时间（流程发起时间）**
- 发起时默认值（可修改）：**需求负责人默认带入发起人**
- 联动规则：复选「其它」/ 验证「不通过」时的必填

## 四、实测时间线（实例 23）

```
发起人提交（申请时间自动记录）
→ 需求负责人（=发起人）同意
→ 业务部门负责人 同意
→ 项目组项目经理 分派项目组经办
→ 项目组经办 提交（优化方案、工时评估、项目经理/信息网络部项目经理）
→ 项目组项目经理 同意
→ 信息网络部项目经理 同意（填写意见）
→ 信息网络部负责人 同意（填写意见）
→ 需求小组组长 同意（指定执行人、复核人）
→ 上线执行人 提交（执行情况）
→ 复核人 提交（复核情况）
→ 需求负责人（=发起人）提交（验证通过）
→ 业务部门负责人 同意
→ 已通过（APPROVED）
```

## 五、与纸质表单的差异 / 当前边界

1. **分管领导审批意见**：纸质审批表有该栏，但你给出的 6 步流程没有这一节点，示例未配置。
   如需要，在「信息网络部负责人审批」之后加一个审批节点即可。
2. **签字**：平台在「处理历史」中记录每个节点的处理人、动作与时间；表单里不自动写入签名栏。
   申请时间已自动记录；执行日期/复核日期/验证日期仍为手工填写的日期字段。
3. **编号**：平台暂无自动流水号规则，编号为手工填写；实例本身有系统生成的编码。
4. **打印版式**：打印内容由表单 schema + 处理历史生成，不是 Word 表格的像素级复刻。
5. **部门负责人解析**：示例为测试方便创建了「业务部（流程测试）」「信息网络部（流程测试）」；
   正式使用时应：
   - 在「部门管理」中给真实业务部门、信息网络部设置负责人；
   - 第 2/12 节点保持「发起人所在部门的主管」；
   - 第 7 节点改为真实信息网络部部门。
6. **需求人员 ≠ 发起人**：示例把「需求人员所在部门」近似为发起人部门；
   若两者可能不同，可增加部门字段，并用 `dept_manager + dept_field` 或 `form_dept_field` 指向该字段。
7. **角色成员**：「项目组项目经理」「需求小组组长」是全局角色，需要在角色管理中维护实际成员。

## 六、如何改成真实组织

1. 部门管理：设置真实业务部门 / 信息网络部的负责人。
2. 角色管理：把「项目组项目经理」「需求小组组长」的成员换成真实人员。
3. 流程设计器：把第 7 节点的指定部门改为真实信息网络部；
   按需把第 1/4/6/9/10/11 节点的人员字段换成指定人员或角色。
4. 表单有改动时：先发布表单新版本，再重新发布流程（发布页会提示旧表单警告）。
