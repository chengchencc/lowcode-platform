## 流程是怎么配的

| 节点 | 审批人来源 |
|---|---|
| 需求负责人审批 | 表单字段「需求负责人」（发起人指定） |
| 需求部门负责人审批 | 发起人所在部门的主管（自动解析） |
| 项目组经办评估并编写方案 | 角色「项目组经办」 |
| 项目组项目经理审批 | 表单字段「项目组项目经理」（第 3 步选择） |
| 信息网络部项目经理审批 | 表单字段「信息网络部项目经理」（第 3 步选择） |
| 信息网络部部门负责人审批 | 指定部门的主管 |
| 需求小组组长审批 | 角色「需求小组组长」；同时指定执行人/复核人 |
| 上线执行人填写执行情况 | 表单字段「上线执行人」 |
| 复核人填写复核情况 | 表单字段「复核人」 |
| 需求负责人填写验证结果 | 表单字段「需求负责人」 |
| 需求部门负责人确认验证 | 发起人所在部门的主管 |

用到的都是现有能力：表单人员字段派单、部门主管动态解析、角色派单、填写节点、按分区的字段权限、发起时自动填充、联动必填（其它模块 / 验证不通过）。

完整说明（字段映射、权限、时间线、如何换成真实组织）见 [REQ-OPT-FLOW-CONFIG.md](docs/REQ-OPT-FLOW-CONFIG.md)。

## 与纸质表单的差异

- 纸质表有**分管领导审批意见**，但你给的 6 步流程里没有这一节点，示例未配；需要的话加一个审批节点即可。
- 签字和日期由「处理历史」记录处理人和时间，不会自动写入表单签名栏；日期栏目前是手填。
- 编号暂无自动流水号，手工填写。
- 打印是按表单 schema + 处理历史生成，不是 Word 表格的像素级复刻。
- 示例用了两个测试部门（业务部/信息网络部-流程测试）和测试账号；换成真实组织时只需把第 6 节点改到真实信息网络部、给部门设负责人、维护两个角色的成员，文档里写了步骤。

重试过程中产生的重复模板已删除或停用，只保留了这套可用示例。
